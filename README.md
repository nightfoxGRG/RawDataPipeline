
# DataPipelinePro / RawDataPipeline

Веб-приложение на Flask для построения пайплайна загрузки сырых данных в PostgreSQL: от инференса структуры таблицы по примеру файла до загрузки данных в БД и анализа качества.

Включает шесть инструментов, выстроенных в единый рабочий процесс:

1. **Параметризатор** — управление подключениями к БД, учётными данными и проектами (схемами).
2. **Конфигуратор** — определение структуры таблиц по загруженному файлу/директории, формирование конфигурационного файла.
3. **Генератор SQL** — формирование SQL-скрипта `CREATE TABLE` по конфигурационному файлу и опциональное выполнение его в рабочей БД.
4. **Маршрутизатор** — настройка маппинга «колонка-источник → колонка таблицы» с функциями преобразования.
5. **Загружатор** — загрузка данных из файлов в таблицы проекта по сохранённым маршрутам.
6. **Анализатор** — поиск дубликатов и качество данных в загруженных таблицах.

## Возможности

### 🗂️ Параметризатор (`/parametrizer`)

Центральный экран управления проектом и подключениями.

- **Настройки базы данных** (db_setting): CRUD списка подключений (label, host, port, name) с проверкой уникальности тройки `(host, port, name)`.
- **Учётные данные подключений** (db_setting_credential): для каждого пользователя — свой логин/пароль на каждое подключение. Кнопка «Проверить подключение» делает реальный `psycopg2.connect` (можно тестировать как с введённым паролем, так и с сохранённым).
- **Проекты** (project): код, описание, привязка к подключению, имя schema в БД. Валидация имени схемы (`^[a-z][a-z0-9_]*$`, минимум 2 символа, запрет на зарезервированные имена `public`, `pg_catalog`, `information_schema`, `pg_toast`, `raw_data_pipline_schema`).
- **Актуальный проект**: каждый пользователь выбирает свой активный проект (user_setting.actual_project_id) — он определяет, к какой schema будут обращаться остальные инструменты.
- **Подсветка плашки проекта в шапке**: после смены проекта обновляется верхний badge с кодом проекта и tooltip-ом с DSN и схемой.
- В **локальном режиме** скрыты блоки логина/учётных данных (single-user сценарий); кнопка «Настройки подключения» ведёт на форму первого запуска `/setup`.

### 🔍 Генератор конфигурационного файла (Конфигуратор, `/configurator` и `/`)

- Принимает файл с данными в форматах `.xlsx`, `.xlsm`, `.csv`.
- Первая строка файла — заголовки колонок (названия на любом языке, включая русский).
- Поддерживает два сценария загрузки:
  - **Один файл** — `POST /table_config_generator`: формируется одна табличная схема.
  - **Директория** — `POST /table_config_generator_from_directory`: пакетная обработка, в одном конфигурационном файле формируется до 5 табличных блоков (формат v2).
- Автоматически **переводит названия колонок и таблиц на английский** через сервис LibreTranslate.
- **Определяет тип PostgreSQL** для каждой колонки по содержимому данных:
  - `boolean` — если все значения `true`/`false`
  - `date` — если все значения в формате `YYYY-MM-DD`
  - `timestamp` — если встречаются значения с временем `YYYY-MM-DD HH:MM...`
  - `integer` / `bigint` — целые числа (до/свыше 2 147 483 647)
  - `numeric(p,s)` — дробные числа с вычисленными точностью и масштабом
  - `varchar(N)` — строки до 255 символов (длина округляется вверх до кратного 50)
  - `text` — строки длиннее 255 символов или колонки без данных
- Формирует **имя SQL-идентификатора колонки** из заголовка: переводит, удаляет недопустимые символы, приводит к `snake_case`. Поле БД с именем `id` автоматически переименовывается в `source_id` (зарезервированное имя — у проекта есть свой автогенерируемый `id`).
- Генерирует конфигурационный файл в формате **`tables_config_v2`** (`.xlsm`) на основе шаблона `TablesConfig.xlsm`.
- Сохраняет сформированный файл в **MinIO** (или в локальный каталог `~/.config/RawDataPipeline/table_configs/` в local-режиме), ссылка кладётся в `project.table_config_minio_id`.
- **Валидация конфигурации**:
  - `GET /table_config_validate_system` — проверка файла, который уже привязан к проекту.
  - `POST /table_config_validate_local` — проверка локально выбранного файла перед загрузкой.
- **Выгрузка/перевыгрузка**:
  - `GET /table_config_download_system` — скачать активный конфиг проекта.
  - `GET /download_table_config_template` — скачать пустой шаблон `TablesConfig.xlsm`.
- При недоступности сервиса перевода выводит понятное сообщение с указанием URL LibreTranslate.

### ⚙️ Генератор SQL (`/generator`, `/sql`)

- Принимает конфигурационный файл в форматах `.xlsx`, `.xlsm`, `.json`.
- Парсит описание таблиц в двух форматах Excel:
  - **v1** (лист `tables_config`) — вертикальные блоки
  - **v2** (лист `tables_config_v2`) — горизонтальные блоки
- Поддерживает **JSON-описание** таблиц (формат `tables_config`).
- Генерирует **корректный SQL-скрипт** `CREATE TABLE` для PostgreSQL:
  - Типы данных с размерностью: `varchar(N)`, `numeric(p,s)` и др.
  - Ограничения: `NOT NULL`, `UNIQUE`, `PRIMARY KEY`, `DEFAULT`, `REFERENCES`
  - Значения `DEFAULT` форматируются согласно типу (числа — без кавычек, строки — в кавычках, SQL-константы `NULL`, `TRUE`, `FALSE`, `now()` и др. — как есть)
  - Выравнивание колонок и комментарии с отображаемым именем
- **Опциональные технические колонки** (флажки на форме):
  - `id bigserial primary key` — автогенерируемый суррогатный ключ.
  - `__source text` — имя файла-источника.
  - `__package_id text` — идентификатор пакета загрузки.
  - `__package_timestamp timestamptz default now()` — отметка времени загрузки.
- **Выполнение SQL в рабочей БД** (`POST /sql_execute`) — DDL прогоняется в schema активного проекта.
- **Валидирует** конфигурацию перед генерацией:
  - Дубликаты таблиц и колонок
  - Имена таблиц/колонок/внешних ключей в формате PostgreSQL (`[A-Za-z_][A-Za-z0-9_]*`)
  - Использование зарезервированных слов PostgreSQL
  - Корректность ссылок внешних ключей (формат `table(column)`)
  - Корректность значений `DEFAULT` для типа колонки
- Отображает SQL прямо на странице.
- Позволяет **скачать шаблон** `TablesConfig.xlsm` для ручного заполнения.
- Позволяет **скачать сгенерированный SQL** как файл `tables.sql`.

### 🔀 Маршрутизатор (`/router`)

Маппинг «колонка в исходном файле → колонка в таблице БД» — определяет, как именно загружать данные.

- **Автогенерация маршрутов** (`POST /source_to_table/generate_from_config`): из конфигурационного файла проекта автоматически создаются записи `source_to_table_config` (один на таблицу) с флагом `is_auto_generated=True` и `source_to_table` для каждой колонки (1-в-1 по имени).
- **Ручное редактирование маршрутов** (визуальный редактор на jsplumb):
  - `GET /source_to_table/schema/tables` — список base-таблиц в схеме проекта (берётся напрямую из `information_schema`).
  - `GET /source_to_table/schema/table-configs` — список маршрутов для выбранной таблицы.
  - `POST /source_to_table/schema/table-configs` — создать новый маршрут (имя, код, описание, тип маппинга, chunk_size).
  - `PATCH /source_to_table/schema/table-configs/<id>` — переименование/обновление описания.
  - `GET /source_to_table/schema/mapping` — получить мэппинги полей.
  - `POST /source_to_table/schema/mapping` — сохранить все мэппинги маршрута.
  - `DELETE /source_to_table/schema/mapping` — удалить все мэппинги.
- **Типы маппинга** (`map_type`):
  - `MAP_BY_COLUMN_NAME` — сопоставление по имени колонки в файле.
  - `MAP_BY_COLUMN_NUMBER` — сопоставление по порядковому номеру колонки.
- **Функции преобразования** (на каждую целевую колонку можно навесить):
  - `SERIAL` — авто-инкремент (внутренний счётчик загрузки).
  - `PACKAGE_TIMESTAMP` — время пакета.
  - `PACKAGE_ID` — идентификатор пакета загрузки.
  - `SOURCE` — имя файла-источника.
  - пустое значение — взять значение из source-колонки как есть.

### 📦 Загружатор (`/loader`)

Загрузка данных в таблицы проекта. Два режима:

- **Загрузка из директории по основному конфигу проекта**
  `POST /loader/load_by_table_config_from_directory` — для каждого файла из выбранной директории система:
  1. Скачивает .xlsm-конфиг проекта из MinIO.
  2. По полю `original_name` ищет блок-таблицу, соответствующую имени файла.
  3. Находит автогенерируемый маршрут (`is_auto_generated=True`) для этой таблицы.
  4. Запускает `LoaderService.load()` — потоковое чтение файла, маппинг колонок, валидация типов, чанковая вставка через `INSERT`.
- **Загрузка с выбором маршрута**
  `POST /loader/directory/load` — пользователь сам выбирает `source_to_table_config` (например, чтобы загрузить «нестандартный» файл в существующую таблицу через другой маппинг).
- **Прогресс и ошибки**: возвращает количество загруженных строк по каждому файлу или список ошибок (несовпадение типа, отсутствующая обязательная колонка, проблема преобразования).
- **Поддерживаемые форматы данных**: `.xlsx`, `.xlsm`, `.csv` (с автоопределением кодировки и разделителя для CSV: UTF-8/BOM, UTF-8, CP1251, latin-1; запятая, точка с запятой, табуляция, пайп).
- **Чанкованная вставка**: размер чанка задаётся на маршруте (`chunk_size`) — позволяет загружать большие файлы без переполнения памяти.
- **Валидация значений на лету**: каждый ряд проверяется на соответствие декларированному типу колонки (int, numeric, bool, date, timestamp).

### 🔬 Анализатор (`/analyzer`)

Поиск дубликатов и проверка качества данных в загруженных таблицах.

- `GET /analyzer/tables` — список доступных таблиц схемы проекта.
- `POST /analyzer/run` — выбор одной или нескольких таблиц + размер чанка, запуск анализа.
- Результат — Excel-отчёт `.xlsx` с отдельным листом на каждую таблицу: ключи группировки, количество совпадений, метрика близости рядов.
- Алгоритм работает чанками, чтобы не нагружать БД и обрабатывать таблицы в десятки миллионов строк.

### 👤 Аутентификация и многопользовательский режим (только server)

- **Keycloak OAuth2 / OIDC**:
  - `GET /login` — редирект на `oauth.keycloak.authorize_redirect()`.
  - `GET /callback` — обработка кода, обмен на токены, upsert пользователя по `email` (`subject_id`).
  - `GET /logout` — очистка сессии + Keycloak logout с `post_logout_redirect_uri`.
- Учётные данные подключения к рабочей БД (`db_setting_credential`) хранятся **на каждого пользователя отдельно** — один проект может разделяться разными людьми с разными правами на БД.
- В local-режиме всё это отключено: единственный пользователь `LOCAL_USER`, авторизация не требуется.

### 🖥️ Режимы запуска

- **Серверный режим** (`APP_MODE=server`, по умолчанию)
  - Запуск через Flask / WSGI / Docker; Keycloak + MinIO; multi-user; `config.toml` + опциональный `config.local.toml`.
  - Фон основной области — белый, бейдж режима — розовый.
- **Локальный режим** (`APP_MODE=local` или PyInstaller-сборка, `sys.frozen=True`)
  - Single-user (`LOCAL_USER`), без Keycloak/MinIO; конфиг лежит в `~/.config/RawDataPipeline/config.local.toml` (или `%APPDATA%\RawDataPipeline\` на Windows); конфигурационные файлы — в `~/.config/RawDataPipeline/table_configs/`.
  - При первом запуске открывается onboarding-форма `/setup` (хост, порт, имя БД, схема, логин/пароль, URL LibreTranslate). После сохранения автоматически применяются миграции и создаётся стартовый `db_setting`.
  - Фон — нежно-голубой, бейдж режима — голубой; в сайдбаре нет блока пользователя.
  - На macOS показывается splash-окно с прогрессом загрузки модулей и поднятия Flask, корректный пункт «Завершить» в Dock через NSApplication.

## Запуск

### Из исходников (server-режим, разработка)

```bash
python -m venv .venv
source .venv/bin/activate       # macOS / Linux
# .venv\Scripts\activate        # Windows
pip install -r requirements.txt
flask --app app run --port 8080
```

Откройте `http://127.0.0.1:8080`.

### Из исходников (local-режим, без Keycloak/MinIO)

```bash
APP_MODE=local python run_app.py
```

При первом запуске откроется форма `/setup` — заполнить параметры PostgreSQL.

### Сервис перевода (LibreTranslate)

Для автоматического перевода заголовков колонок с русского на английский требуется запущенный экземпляр [LibreTranslate](https://libretranslate.com/).

URL сервиса задаётся в файле `config.toml`:

```toml
[translation]
libretranslate_url = "http://127.0.0.1:50001"
api_key = ""   # опционально
```

Запуск через Docker Compose:

```bash
docker compose -f docker/libretranslate.yml up -d
```

### PostgreSQL, MinIO, Keycloak (server-режим)

В каталоге `docker/` лежат compose-файлы для всей инфраструктуры — см. `docker/запуск`.

Приложение можно собрать в самостоятельный исполняемый файл для macOS и Windows с помощью [PyInstaller](https://pyinstaller.org/):

| Платформа | Результат                       | Запуск                                              |

## Конфигурация

### `resources/config.toml` (база, всегда читается)

```toml
[app]
project_name = "RawDataPipeline"
secret_key = "..."

[database]          # рабочая БД (метаданные проекта + рабочие схемы)
host = "localhost"
port = 5432
name = "raw_data_pipeline"
schema = "raw_data_pipline_schema"
user = "postgres"
password = "..."

[translation]
libretranslate_url = "http://127.0.0.1:50001"
api_key = ""

[minio]             # только server-режим
endpoint = "localhost:50002"
access_key = "..."
secret_key = "..."

[keycloak]          # только server-режим
server_url = "http://localhost:50004"
realm = "master"
client_id = "raw-data-pipeline"
client_secret = "..."
```

### `config.local.toml` (override)

- В **server-режиме** читается при `APP_ENV=local` из `resources/config.local.toml`.
- В **local-режиме** читается из `~/.config/RawDataPipeline/config.local.toml` (или `%APPDATA%\RawDataPipeline\config.local.toml`). Создаётся автоматически при первом запуске.
- Значения **deep-merge**-ются поверх базового `config.toml`.

## Поддерживаемые форматы конфигурации

### Excel v1 (лист `tables_config`)

Каждая таблица — вертикальный блок. Первая строка блока — имя таблицы, далее строки-атрибуты:

| Строка (столбец A)         | Обязательная | Описание                                              |
|----------------------------|:---:|-------------------------------------------------------|
| Наименование таблицы       | ✔   | Имя таблицы в БД; значение — в столбцах B+            |
| Код колонки в БД           | ✔   | Коды колонок (по одному на столбец, начиная с B)      |
| Тип                        | ✔   | Тип данных PostgreSQL                                 |
| Размерность                |     | Например `50` или `10,2`                              |
| Описание                   |     | Отображаемое наименование колонки                     |
| Обязательность             |     | `да` — NOT NULL                                       |
| Уникальность               |     | `да` — UNIQUE                                         |
| Первичный ключ             |     | `да` — PRIMARY KEY                                    |
| Внешний ключ               |     | Ссылка в формате `table(column)`                      |
| Значение по умолчанию      |     | Значение DEFAULT для колонки                          |

### Excel v2 (лист `tables_config_v2`)

Таблицы — горизонтальные блоки, разделённые пустым столбцом. Каждая колонка — отдельная строка.

**Строка 1** — имя таблицы. **Строка 2** — заголовки атрибутов. **Строки 3+** — данные колонок.

| Заголовок (строка 2)      | Обязательный | Описание                                      |
|---------------------------|:---:|-----------------------------------------------|
| Описание                  | ✔   | Признак начала блока; наименование колонки    |
| Код колонки в БД          | ✔   | Код колонки в БД                              |
| Тип                       | ✔   | Тип данных PostgreSQL                         |
| Размерность               |     | Например `50` или `10,2`                      |
| Обязательность            |     | `да` — NOT NULL                               |
| Уникальность              |     | `да` — UNIQUE                                 |
| Первичный ключ            |     | `да` — PRIMARY KEY                            |
| Внешний ключ              |     | Ссылка в формате `table(column)`              |
| Значение по умолчанию     |     | Значение DEFAULT для колонки                  |

### JSON

```json
{
  "tables_config": [
    {
      "table_name": "users",
      "columns": [
        {
          "column_code": "id",
          "type": "bigserial",
          "nullable": false,
          "primary_key": true
        },
        {
          "column_code": "email",
          "type": "varchar",
          "size": "255",
          "nullable": false,
          "unique": true,
          "column_name": "Электронная почта"
        },
        {
          "column_code": "role_id",
          "type": "bigint",
          "nullable": true,
          "foreign_key": "roles(id)"
        }
      ]
    }
  ]
}
```

Поле `tables_config` — список объектов или словарь `{ "table_name": { columns } }`.

| Поле колонки  | Тип    | Описание                                           |
|---------------|--------|----------------------------------------------------|
| `column_code` | string | Код колонки в БД (обязательное)                    |
| `type`        | string | Тип данных PostgreSQL (обязательное)               |
| `size`        | string | Размерность, например `"255"` или `"10,2"`         |
| `nullable`    | bool   | `true` — допускает NULL (по умолчанию `true`)      |
| `unique`      | bool   | `true` — UNIQUE (по умолчанию `false`)             |
| `primary_key` | bool   | `true` — PRIMARY KEY (по умолчанию `false`)        |
| `foreign_key` | string | Ссылка в формате `table(column)`                   |
| `default`     | string | Значение по умолчанию                              |
| `column_name` | string | Отображаемое наименование колонки                  |

## Автоопределение типов PostgreSQL

| Условие                                      | Тип PostgreSQL       |
|----------------------------------------------|----------------------|
| Все значения `true` / `false`                | `boolean`            |
| Все значения в формате `YYYY-MM-DD`          | `date`               |
| Есть значения с временем `YYYY-MM-DD HH:MM…` | `timestamp`          |
| Целые числа ≤ 2 147 483 647                  | `integer`            |
| Целые числа > 2 147 483 647                  | `bigint`             |
| Дробные числа                                | `numeric(p,s)`       |
| Строки ≤ 255 символов                        | `varchar(N)` (N кратно 50, минимум 50) |
| Строки > 255 символов или пустая колонка     | `text`               |

## Схема системной БД

Системная схема (по умолчанию `raw_data_pipline_schema`) хранит метаданные приложения:

| Таблица                    | Назначение                                                                   |
|----------------------------|------------------------------------------------------------------------------|
| `users`                    | Пользователи (Keycloak subject_id или `LOCAL_USER`); поле `is_tech_user`     |
| `db_setting`               | Подключения к рабочим БД (host, port, name, label)                           |
| `db_setting_credential`    | Логин/пароль на каждую пару `(user, db_setting)`                             |
| `project`                  | Проекты: код, описание, привязка к `db_setting`, имя schema, ссылка на конфиг (`table_config_minio_id`) |
| `user_setting`             | Активный проект на каждого пользователя (`actual_project_id`)                |
| `source_to_table_config`   | Маршруты загрузки: имя таблицы, код, тип маппинга, размер чанка, флаг автогенерации |
| `source_to_table`          | Поля маршрутов: source-колонка/номер, целевая колонка, функция преобразования |

Миграции применяются автоматически (yoyo-migrations); файлы — в `resources/migrations/`. Служебная таблица `_yoyo_migration` тоже создаётся в системной схеме.

## Внешние интеграции

| Сервис          | Назначение                                                            | Когда нужен          |
|-----------------|-----------------------------------------------------------------------|----------------------|
| **PostgreSQL**  | Основное хранилище: системные таблицы + схемы проектов                | всегда               |
| **LibreTranslate** | Перевод заголовков русских колонок в snake_case-имена для БД        | при работе Конфигуратора |

## Архитектура

```
src/
├── app.py                       # Flask routes, app factory, middleware
├── run_app.py                   # PyInstaller entry-point (local-режим)
├── common/                      # утилиты: контексты, ошибки, paths, декораторы
├── config/                      # AppMode, config_loader, keycloak, миграции, ORM/engine
└── domains/                     # бизнес-домены (по фичам, не по техническим слоям)
    ├── db_setting/              # подключения
    ├── db_setting_credential/   # учётные данные
    ├── project/                 # проекты (schema-namespace)
    ├── users/                   # пользователи + user_setting (актуальный проект)
    ├── configurator/            # инференс структуры из файлов
    ├── generator/               # CREATE TABLE SQL
    ├── source_to_table/         # маршруты загрузки + ручной маппинг
    ├── loader/                  # загрузка данных в БД
    ├── analyzer/                # анализ дубликатов
    ├── libretranslate/          # перевод
    ├── minio/                   # объектное хранилище
    └── working_db/              # выполнение запросов в схеме проекта
```

Каждый домен — три файла: `*_service.py` (Flask-эндпоинты-обёртки и бизнес-логика), `*_repository.py` (доступ к БД), `*_model.py` (SQLAlchemy ORM).
